# 写作与图表规范

## 1. 语气

- 第一人称、克制、具体；避免"精通""极致""颠覆"等营销词。
- 用事实与约束说明能力，例如"在 4 周内完成数据清洗与基线模型，准确率提升 6 个百分点"。
- 区分"负责/参与/独立完成"，不夸大。
- 反思部分允许暴露不足，但必须给出改进方向。

## 2. 中文排版

- 中文与英文、数字之间留一个空格：`7 个领域`、`12 个项目`、`Astro 7`。
- 中文标点用全角，英文括号与代码用半角。
- 不使用连续感叹号；破折号用 `——`。
- 数字：小于 10 用汉字（三个），≥10 用阿拉伯数字（12 个），度量与版本一律阿拉伯数字。
- 术语首现：中文（English），此后统一用中文或统一用英文，不混用。

## 3. 标题层级

- 页面 H1 唯一；文档内从 H2 开始。
- 标题不使用句号；不超过 20 字。
- 项目正文固定六个 H2，顺序不可变。
- 标题中不使用加粗或代码（除非是命令名）。

## 4. 段落与列表

- 一段 3–5 行；移动端不超过 6 行。
- 列表项保持平行结构；并列项不超过 7 条。
- 表格用于对比与字段说明，不用于长段落。

## 5. 代码与命令

- 行内代码用于文件名、字段、命令、类型。
- 命令块标注语言：`bash`、`ts`、`yaml`、`json`、`css`。
- 危险命令（删除、强推、覆盖）必须附说明与确认步骤。
- 不写无法验证的命令；注明版本前提。

## 6. 图表

- 架构与流程用 Mermaid；页面线框用 ASCII。
- 图必须有标题与一句话说明；颜色不单独承载信息。
- 截图需脱敏，保留 2x 分辨率，文件名含用途。

## 7. 引用

- 引用外部资料注明来源与访问日期。
- 不复制大段受版权保护的文字；数据需注明口径。
- 使用他人在先作品（图片/图表）必须确认许可。

## 9. 提交信息

遵循 Conventional Commits，type 用英文、摘要用中文祈使句：

```
feat(projects): 增加领域筛选与 URL 状态同步
fix(seo): 修正子路径部署下的 canonical
docs(adr): 记录 TypeScript 版本选择
```

## 10. 变更记录

`CHANGELOG.md` 使用 Keep a Changelog 分类：Added / Changed / Deprecated / Removed / Fixed / Security；每条写用户可感知的变化。
