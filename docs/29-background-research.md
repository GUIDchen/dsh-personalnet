# 站点背景与动态视觉调研

## 1. 目标

让背景从"纯色画布"变成有辨识度的环境层，同时满足：

- 不干扰正文阅读，正文对比度不下降；
- 无布局偏移、无额外图片请求、无第三方运行时；
- 支持浅色/深色主题；
- 尊重 `prefers-reduced-motion`；
- 移动端与低性能设备可降级；
- 不突破现有 CSS/JS 预算。

## 2. 候选方案

| 方案 | 优点 | 代价/风险 | 结论 |
|---|---|---|---|
| 静态图片/摄影背景 | 氛围强、可控 | 需要授权素材；深色/浅色两套；图片体积与 LCP；文字对比度难控 | 暂不采用 |
| CSS 渐变/极光 | 零 JS、零请求、易主题化 | 容易过于"模板感" | 采用（环境层） |
| CSS 3D 透视网格 | 有空间感、零 JS、GPU 合成 | 低端设备需降透明/移动端简化 | 采用（结构层） |
| Canvas 粒子/星座 | 动态感强 | 需要 RAF、CPU/电量、可访问性与降级复杂 | 不采用 |
| Three.js / WebGL / Spline | 真 3D、可交互 | 包体大（100KB+）、GPU/电量、加载与降级成本 | 不采用 |
| 视频背景 | 观感强 | 自动播放、体积、流量、可访问性 | 不采用 |

## 3. 决策

实现 `SiteBackground`：

- 两层纯 CSS：
  - **aurora**：低透明度的 accent/fg 径向渐变，28s 缓慢漂移；
  - **grid**：透视旋转的 CSS 网格，22s 纵向漂移，mask 上下淡出。
- 背景固定在视口，`z-index: -1`，`pointer-events: none`，不参与布局；
- 通过 `color-mix` 跟随主题 token；
- 移动端降低网格透明度与尺寸；
- `prefers-reduced-motion: reduce` 时停止所有动画；
- 后台 `bare` 页面不挂载背景。

## 4. 为什么不选 WebGL/3D

- 站点是内容优先的静态站，3D 背景不会提升可读性；
- Three.js 会引入远大于当前全部 JS 的包体，并与"零运行时"目标冲突；
- WebGL 在低端设备/远程桌面/部分浏览器上需要降级，维护成本高；
- 若未来确实需要可交互 3D，应作为独立的实验页按需加载，而不是全站背景。

## 5. 验证

- Lighthouse 12 页（含背景）通过；
- axe 22 页 0 serious/critical；
- 背景无图片请求、无 JS；
- 浅色/深色截图走查；
- 视觉上正文卡片仍保持 `--surface` 可读背景。

## 6. 后续可选

- 背景强度/开关（存储用户偏好）；
- 独立的 WebGL/Spline 实验页，按需加载并单独预算；
- 真实项目截图作为项目页背景（需授权与压缩）。
