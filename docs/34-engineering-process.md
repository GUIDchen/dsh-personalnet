# 软件工程开发流程

本文定义项目从需求到退役的生命周期、角色、工件、检查点与变更控制。它不重复技术细节；架构见 05，测试见 10，发布见 25，运维见 11/17/37。

## 1. 范围与原则

- 单人维护 + AI 编码代理参与，流程必须轻量但不能跳过验证。
- 静态站点、内容驱动、零运行时后端；所有变更可通过 Git 审计和回滚。
- 先定义验收，再实现；文档与代码同仓、同提交。
- 自动化优先：能由 CI 检查的，不靠记忆；不能自动化的，写成手工清单。
- 不伪造数据、截图、指标或外部集成状态。

## 2. 生命周期

~~~mermaid
flowchart LR
  A[发现/目标] --> B[需求与验收]
  B --> C[设计与 ADR]
  C --> D[实现与内容]
  D --> E[本地验证]
  E --> F[CI 与评审]
  F --> G[发布]
  G --> H[运行与观测]
  H --> I[复盘与退役]
  I --> A
~~~

| 阶段 | 主要工件 | 出口条件 |
|---|---|---|
| 发现 | 目标、约束、风险 | 范围与非目标明确 |
| 需求 | 02 需求、用户故事、NFR | 验收标准可测 |
| 设计 | 05 架构、ADR、07/08/09 | 方案与替代方案有记录 |
| 实现 | 代码、内容、测试、文档 | 本地检查通过 |
| 验证 | CI、E2E、axe、LHCI、内容检查 | 门禁全绿 |
| 发布 | CHANGELOG、tag、release | 公网 200、回滚点存在 |
| 运行 | 维护日志、健康报告 | 异常有记录、有负责人 |
| 退役 | 迁移/归档说明 | 链接与数据有去向 |

## 3. 角色与职责

单人项目采用“角色帽子”而非多人组织：

| 角色 | 职责 |
|---|---|
| 产品负责人 | 目标、优先级、非目标 |
| 架构/技术负责人 | 边界、ADR、质量属性 |
| 实现者 | 代码、内容、测试 |
| 评审者 | 独立视角检查需求/安全/回归 |
| 发布负责人 | 版本、tag、release、回滚 |
| 运维负责人 | 部署、监控、事故、恢复 |
| 内容负责人 | 事实、隐私、双语一致性 |

AI 代理可以承担实现、检查和文档起草，但不能替代作者对事实、隐私与发布的最终确认。

## 4. 工作项与优先级

- 工作项类型：需求、缺陷、技术债、内容、文档、运维。
- 优先级：P0（上线/安全/数据）> P1（核心体验/质量门禁）> P2（增强）> P3（想法）。
- 每个工作项至少有：背景、验收标准、影响面、回滚方式。
- 范围蔓延处理：新需求进入 13 Backlog，不混入当前发布；紧急修复走 hotfix。

### 4.1 Definition of Ready

1. 目标与非目标清楚。
2. 验收标准可执行（命令/页面/指标）。
3. 依赖与外部凭据已确认。
4. 涉及内容时有事实来源，不编造。
5. 涉及架构时已有 ADR 或明确不需要。

### 4.2 Definition of Done

1. 实现与测试同提交；相关文档/ADR 同步。
2. 本地 lint、check、unit、build、content、security、SEO 通过。
3. 涉及 UI 时有桌面/移动截图与 axe 结果。
4. 涉及内容时通过隐私/证据/双语检查。
5. 性能/体积预算未回归；必要时记录豁免理由。
6. CHANGELOG 记录；发布项有 tag/release。
7. 部署后公网检查通过，回滚点明确。

## 5. 变更控制

- 分支：main 始终可发布；功能分支短生命周期；提交遵循 Conventional Commits。
- 评审：至少一次独立检查（人工或代理审查），重点看需求偏差、安全、回归、文档。
- 高风险变更：认证/权限、CSP、部署、内容 schema、删除页面、外部集成。需要 ADR + 回滚方案 + 发布后验证。
- 禁止：直接改 main 的历史提交、强推共享分支、把密钥写入仓库、未经确认修改事实数据。
- 回滚：优先 revert 提交；部署回滚见 11/37；数据回滚依赖 Git 与发布 tag。

## 6. 测试与质量门禁

测试金字塔：

- 单元：纯函数、schema、路由、时间线、SEO 日期。
- 集成：构建产物、链接、JSON/feed、CSP、预算。
- E2E：关键用户路径、双语、实验/时间线降级。
- 手工：读屏、键盘、真机 Safari、内容事实审阅。

合并门禁：lint、format、astro check、unit/coverage、build、docs/content/site/media/github/security/translations/admin/contrast/SEO/budget、E2E、axe、LHCI。

## 7. 发布与运行

- 版本语义：新增向后兼容功能为 minor，修复为 patch，破坏性路由/数据契约为 major。
- 发布前：25 清单；发布后：公网 200、CSP/headers、双站部署、Search、admin。
- 运行：健康报告、维护日志、月度依赖升级、季度恢复演练。
- 支持级别：个人项目，尽力而为；安全问题优先于内容更新。

## 8. 文档与 ADR

- 文档分级：愿景/需求/架构/实现规范/质量/运维/审计。
- 新决策先写 ADR；已接受的 ADR 不修改结论，只追加后续变更。
- 文档必须可导航：docs/README 索引、README 入口、相关文档互链。
- 文档过期即缺陷；每次发布检查 19/24/25 与版本号。

## 9. 度量与复盘

| 度量 | 目标 | 来源 |
|---|---|---|
| CI 通过率 | ≥95% | GitHub Actions |
| 部署成功率 | 100% | deploy workflows |
| 严重可访问性问题 | 0 | axe |
| 内容完整性 | 18/18 双语 | check:translations |
| 性能回归 | 不超预算 | LHCI |
| 事故恢复 | 见 37 RTO/RPO | 维护日志 |

复盘只记录事实、根因、行动项与负责人；行动项进入 Backlog，不停留在口头。
