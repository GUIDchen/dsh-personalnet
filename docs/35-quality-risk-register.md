# 质量属性、风险登记与技术债

本文是质量与风险的单一登记处。测试细节见 10，架构见 05，完成度见 19。

## 1. 质量属性场景

| ID | 属性 | 场景 | 响应 | 度量 |

## 5. 技术债处理规则

1. 新债必须登记 ID、影响、触发条件与偿还建议。
2. P0 债在下一个发布前处理；P1 在一个月内评估；P2 进入路线图。
3. 偿还债时先补测试/检查，再改实现。
4. 不把“以后重构”作为跳过测试或文档的理由。

## 6. 质量评审清单

- 是否有可测验收标准？
- 是否覆盖失败路径/降级/空态？
- 是否影响双语、base path、CSP、SEO、性能预算？
- 是否有回滚点与发布后检查？
- 是否新增了未登记的技术债？
