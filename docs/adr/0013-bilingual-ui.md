# ADR 0013：双语界面采用 /en 前缀与页面组件复用

## 状态

Accepted（2026-10-23）

## 背景

站点是静态输出，中文为默认语言。需要在不引入运行时后端、不复制整页模板的前提下，提供可分享、可索引的英文界面，并保留项目/笔记正文为中文。

## 决策驱动因素

- SEO：英文页面需要独立 URL、canonical 与 hreflang。
- 维护成本：6 个页面的布局与样式不应复制两份。
- 静态优先：不能依赖 cookie 或运行时重定向。
- 渐进式：正文翻译可以后补，不影响界面先上线。

## 考虑过的选项

- **客户端切换（localStorage）**：实现最快，但没有独立 URL，SEO 与分享差。
- **Astro i18n 自动路由 + fallback**：需要把页面移入 locale 目录，并为缺翻译页面配置 fallback；与现有扁平路由冲突。
- **为英文复制整套页面**：实现直接，但样式与逻辑双份维护。
- **显式 `/en/` 路由 + 页面组件复用**：中文页面接受 `lang`，英文路由薄包装导入页面组件并传 `lang="en"`。

## 决策

采用显式 `/en/` 路由与页面组件复用：

- 默认中文保持在根路径；英文在 `/en/` 下。
- `src/i18n` 提供字典、页面文案与路由 helper。
- 页面组件通过 `lang` 选择文案、个人资料与链接；`src/pages/en/*` 只做导入与传参。
- 项目/笔记详情不生成英文版；语言切换回退到对应英文列表。
- hreflang 只对存在的对等页输出。

## 后果

### 正面

- 每个英文页面有独立 URL、canonical 与 hreflang。
- 布局与样式只有一份，新增语言时主要补字典。
- 正文翻译可以按条目逐步补齐，不阻塞界面。

### 负面

- 页面组件同时承担"页面"和"被英文路由复用"两种角色，需在文档中明确。
- 字典与页面文案需要同步维护，缺失由类型检查兜底。
- 英文页混合中文正文，需要 `lang` 标注与提示；完整体验仍依赖正文翻译。
