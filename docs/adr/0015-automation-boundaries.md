# ADR 0015：自动化边界：定时审计 + 受控 Agent 长跑

## 状态

Accepted（2026-10-23）

## 背景

站点依赖内容、依赖、SEO、性能与链接的持续健康。希望"长时间自动审阅、自动完善、自动执行"，但个人项目无法承担全自动合并带来的回归与内容错误风险。

## 决策驱动因素

- 早期发现回归，而不是等用户访问时发现。
- 修复动作可审计、可回滚。
- 不引入额外的服务器或密钥管理。
- 内容与视觉决策仍需作者控制。

## 考虑过的选项

- **全自动修复并提交 main**：速度最快，但内容错误、样式回归与安全风险不可控。
- **定时审计 + Issue**：只读、安全，但需要人工/Agent 后续修复。
- **定时审计 + 自动修复 PR**：平衡，但需要更复杂的权限与合并策略。
- **仅 Agent 长跑**：依赖会话，无法在无人时发现回归。

## 决策

采用"定时审计 + 受控 Agent 长跑"：

- GitHub Actions 每周运行健康检查，更新单个 maintenance Issue；不自动提交。
- Agent 在 DSH goal 中按轮次实现、测试、本地 commit，不 push、不自动合并。
- 低风险修复（格式、内部链接、依赖升级）可本地完成或通过 Dependabot PR；内容/翻译/视觉需人工确认。
- 每轮写入维护日志；报告作为 artifact/Issue 保留。

## 后果

### 正面

- 回归可见，修复有测试与 commit 记录。
- 权限最小化，不需要给 CI 写权限。
- 作者保留内容与视觉的最终决定权。

### 负面

- 发现问题后仍需一轮 Agent/人工处理，不是即时自愈。
- 定时任务与 Agent 都需要维护成本。
- 报告可能因外部链接抖动产生噪音，需要区分 403/405 与真实 404。
